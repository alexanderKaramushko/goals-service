# Бизнес-правила

## Назначение документа

Документ описывает действующие и запланированные правила работы с целями,
шагами и наградами. Он не описывает API и внутреннее устройство системы.

Для правил используются четыре статуса:

- **Реализовано** — правило действует в системе;
- **Частично реализовано** — возможность существует, но не все ожидаемые
  ограничения действуют;
- **Запланировано** — возможность описана в планах, но пока недоступна;
- **Требует проверки** — текущее поведение известно, но ожидаемое бизнес-правило
  не определено однозначно.

## Общие понятия

- **Пользователь** — участник системы, который создаёт цели, выполняет шаги и
  может назначать награды другим пользователям.
- **Цель** — результат, которого пользователь хочет достичь к определённой
  дате.
- **Шаг** — промежуточное действие, связанное с целью.
- **Награда** — обещание от другого пользователя за успешное выполнение цели.

У одного пользователя может быть несколько целей. У одной цели может быть
несколько шагов и наград от разных пользователей.

| Область      | Правило или возможность                              | Статус               |

## Пользователи и доступ

### Доступ к операциям

**Статус:** Реализовано

**Правила:**

- доступ к операциям с пользователями, целями, шагами и наградами возможен
  только после успешной аутентификации;
- текущий пользователь определяется системой, а не указывается клиентом при
  изменении данных.

### Владение и видимость данных

**Статус:** Частично реализовано

**Правила:**

- изменять статус, завершать, отменять и удалять цель может только её владелец;
- завершать и удалять шаг может только владелец связанной цели;
- пользователь может получить список собственных целей;
- при создании и просмотре шагов владение целью сейчас не проверяется.

## Цели

### Создание цели

**Статус:** Реализовано

**Предусловия:**

- пользователь аутентифицирован;
- указаны название, описание и дедлайн цели;
- название и описание не пусты;
- дедлайн позже текущего дня пользователя.

**Результат:**

- создаётся цель текущего пользователя;
- цель получает статус `created`.

### Получение целей

**Статус:** Реализовано

**Правила:**

- пользователь может получить список собственных целей;
- в список входят цели во всех статусах;
- каждая цель возвращается со связанными шагами и наградами;
- для каждой цели определяется, является ли она просроченной;
- порядок целей, шагов и наград не определён;
- получение одной цели отдельной операцией не поддерживается.

### Статусы цели

**Статус:** Реализовано

**Правила:**

| Статус      | Значение                                |
| ----------- | --------------------------------------- |
| `created`   | Цель создана, но ещё не запущена.       |
| `active`    | Цель запущена, её шаги можно выполнять. |
| `completed` | Цель завершена с итоговым комментарием. |
| `cancelled` | Работа над активной целью прекращена.   |

Разрешены следующие переходы:

- `created` → `active`;
- `active` → `completed`;
- `active` → `cancelled`.

Цель в статусе `created` также можно удалить. Повторные и обратные переходы не
допускаются.

### Просроченность цели

**Статус:** Реализовано

**Правила:**

- незавершённая цель просрочена, если её дедлайн раньше текущего дня
  пользователя;
- завершённая цель просрочена, если дата завершения позже дедлайна;
- совпадение даты завершения и дедлайна не считается просрочкой;
- статус цели сам по себе не влияет на просроченность.

### Активация цели

**Статус:** Реализовано

**Предусловия:**

- цель существует и принадлежит текущему пользователю;
- цель находится в статусе `created`;
- дедлайн цели не прошёл;
- у цели нет шагов с прошедшим дедлайном.

**Ограничения:**

- цель можно активировать без шагов;
- цель с дедлайном на текущий день можно активировать.

**Результат:** цель получает статус `active`.

### Завершение цели

**Статус:** Реализовано

**Предусловия:**

- цель существует и принадлежит текущему пользователю;
- цель находится в статусе `active`;
- дедлайн цели не прошёл;
- указан итоговый комментарий;
- каждый шаг либо завершён, либо уже просрочен.

**Ограничения:**

- незавершённый непросроченный шаг блокирует завершение цели;
- незавершённый просроченный шаг не блокирует завершение;
- цель без шагов можно завершить;
- возможность назначить награду зависит от доли незавершённых просроченных
  шагов;
- награда разрешается, только если эта доля меньше установленного порога.

**Результат:**

- цель получает статус `completed`;
- сохраняются дата завершения и итоговый комментарий;
- фиксируется возможность назначать награды на цель.

### Отмена цели

**Статус:** Реализовано

**Предусловия:** цель принадлежит текущему пользователю и находится в статусе
`active`.

**Результат:** цель получает статус `cancelled`, дата отмены сохраняется.

### Удаление цели

**Статус:** Реализовано

**Предусловия:** цель принадлежит текущему пользователю и находится в статусе
`created`.

**Результат:** цель и связанные с ней шаги и награды удаляются без возможности
восстановления.

## Шаги

### Создание шага

**Статус:** Частично реализовано

**Предусловия:**

- пользователь аутентифицирован;
- цель существует;
- указаны название, описание и дедлайн шага;
- название и описание не пусты;
- дедлайн позже текущего дня пользователя;
- у цели нет другого шага с таким же дедлайном.

**Ограничения:**

- у одной цели не может быть двух шагов с одинаковым дедлайном;
- принадлежность цели текущему пользователю не проверяется;
- статус цели не проверяется: сейчас шаг можно создать и после активации,
  завершения или отмены цели;
- дедлайн шага не сравнивается с дедлайном цели.

**Результат:** создаётся новый шаг, связанный с целью.

### Получение шагов

**Статус:** Требует проверки

**Правила:**

- пользователь может запросить шаги выбранной цели;
- принадлежность цели текущему пользователю не проверяется;
- возвращаются шаги только целей в статусах `created` и `active`;
- завершённые шаги также входят в список;
- для каждого шага определяется, является ли он просроченным;
- порядок шагов не определён.

### Порядок выполнения шагов

**Статус:** Реализовано

**Правила:**

- следующим считается незавершённый непросроченный шаг с самым ранним
  дедлайном;
- просроченные шаги пропускаются;
- одинаковые дедлайны внутри одной цели запрещены.

### Просроченность шага

**Статус:** Реализовано

**Правила:**

- незавершённый шаг просрочен, если его дедлайн раньше текущего дня
  пользователя;
- завершённый шаг просрочен, если дата завершения позже дедлайна;
- совпадение даты завершения и дедлайна не считается просрочкой.

### Завершение шага

**Статус:** Реализовано

**Предусловия:**

- шаг существует и относится к цели текущего пользователя;
- цель находится в статусе `active`;
- шаг ещё не завершён;
- дедлайн шага не прошёл;
- шаг является следующим по порядку выполнения;
- указан итоговый комментарий.

**Ограничения:** повторное завершение шага запрещено.

**Результат:** сохраняются дата завершения шага и итоговый комментарий.

### Удаление шага

**Статус:** Реализовано

**Предусловия:** шаг относится к собственной цели пользователя в статусе
`created`.

**Результат:** шаг удаляется без возможности восстановления.

## Награды

### Назначение награды на цель

**Статус:** Реализовано

**Предусловия:**

- пользователь аутентифицирован;
- цель существует и принадлежит другому пользователю;
- цель находится в статусе `completed`;
- по результатам завершения цели награды разрешены;
- указаны название и описание награды;
- текущий пользователь ещё не назначал награду этой цели.

**Ограничения:**

- один пользователь может назначить конкретной цели только одну награду;
- разные пользователи могут назначить одной цели разные награды;
- назначить награду собственной цели нельзя.

**Результат:** награда связывается с целью и пользователем, который её
назначил.

### Награда пользователю

**Статус:** Запланировано

**Правила:**

Планируется возможность назначать награду непосредственно пользователю. Правила
стоимости награды и использования звёзд пока не определены в приложении.

## Работа с датой и часовым поясом

### Дедлайны

**Статус:** Реализовано

**Правила:**

- дедлайны целей и шагов определяются календарной датой без учёта времени;
- текущий день определяется с учётом часового пояса пользователя;
- дедлайн на текущий день ещё не считается просроченным;
- создать цель или шаг с дедлайном на текущий день нельзя.

## Открытые вопросы

1. Должен ли шаг создаваться только владельцем цели и только пока цель находится
   в статусе `created`?
2. Должны ли шаги завершённых и отменённых целей оставаться доступными для
   просмотра?
3. Должен ли дедлайн шага быть не позже дедлайна цели?
4. Должны ли завершённые с опозданием шаги влиять на возможность назначения
   награды? Сейчас они считаются просроченными при просмотре, но не входят в
   расчёт доли просрочки при завершении цели.
5. Какое значение порога просроченных шагов является бизнес-стандартом?
6. Остаются ли в плане уведомления о приближении дедлайна и просрочке шага,
   описанные в старой документации?
